# Task 1
Implement merge sort in Python and test it on a random list. Use a list data structure implemented in Assignment 2. Measure the runtime for growing input sizes and compare it with the theoretical O(n log n) bound.

## Use singly linked list
- Reason: one pointer per node, less memory than a doubly linked list. Although its append walks the whole list (O(n)), but I let merge to keep its own reference to the last node of the result, so each element is added in O(1), merge runs in O(m + n), and the whole sort in O(n log n).

## Runtime measurement

| n | time (s) | time / (n log₂ n) [ns] |
|---|---|---|
| 1000  | 0.0037 | 374.8 |
| 2000  | 0.0080 | 362.9 |
| 4000  | 0.0166 | 347.5 |
| 8000  | 0.0361 | 348.4 |
| 16000 | 0.0823 | 368.1 |
| 32000 | 0.1899 | 396.5 |

If the runtime is c · n log n, then time / (n log n) should stay roughly constant. It stays between about 350 and 400 ns while n grows 32 times, so the measurements match the theoretical O(n log n) bound.

When n doubles, the time grows by a factor of about 2.1–2.3, close to the expected 2·log(2n)/log(n) ≈ 2.15 for n log n, and far from the factor 4 of an O(n²) algorithm. The small increase for the largest n is likely due to cache effects (nodes spread out in memory), which changes the constant c, not the growth rate.
